# 독자 설계 4인용 맵 — 구조와 검증

v0.5.3에서는 제공된 SCM/SCX와 로컬 CV5/VF4에서 변환한 `data/original_maps.json`을 사용한다. 원본 배치·높이·통행·건설 가능 여부를 적용하며, 충돌은 AsteraCraft의 32픽셀 격자로 변환된다. 상세 내용은 `docs/changes-v053.txt` 참고. 아래 분석은 이전 독자맵의 이력이며 `data/maps.json`은 구버전 리플레이용으로 유지한다.

맵은 모두 128×128이며 논리 한 칸은 32px이다. 네 슬롯은 북서·북동·남동·남서 순이다. 세 맵의 실제 지형 마스크, 이동 경로, 고도와 중앙 구조가 다르다.

| 지도 | 실제 구조 | 물 칸 | 암반 칸 | 고지 칸 | 중앙 |
| --- | --- | ---: | ---: | ---: | --- |
| 황철 분지 | 넓은 중앙 분지, 모서리 고지 본진, 외곽 암반 우회 | 328 | 2388 | 5952 | 개방 교전장 |
| 과숙의 심장 | 중앙 호수, 안쪽 순환 고리, 바깥 우회로 | 1576 | 2448 | 6024 | 이동 불가 호수 |
| 적월의 성역 | 네 석재 성채, 중앙 고지, 대각선 및 외곽 연결교 | 3772 | 1648 | 12612 | 고지 교전장 |

다리 메타데이터는 성역에만 12개 존재한다. 반사된 외곽 다리 구간은 중앙에서 이어지므로 물리적으로 독립한 다리 12개라는 뜻은 아니다.

## 네 시작점의 공정성

모든 판정 자료는 좌우 및 상하 반사(D2)로 생성한다. 2×1 광물과 4×2 가스를 가로로 고정한 채 네 시작점의 자원 충돌까지 정확히 대응시키기 위한 선택이다. 90도 회전 대칭이라고 표시하지 않는다. 반사 중심은 `(63.5,63.5)`이다.

`terrain`, `height_map`, `surface_map`, `detail_map`, `buildable_map`의 모든 칸을 양축 대조한다. 자원 위치·초기량·풋프린트, 장식 위치·종류·변형·크기도 양축으로 대응한다. 생성형 재질의 미세 무늬는 시각 장식이며 충돌을 바꾸지 않는다.

시작 본부는 5×4칸이므로 단순히 정수 시작점에 같은 원점을 빼면 상하 반사 때 한 칸이 어긋난다. `start_building_anchor(slot,size)`는 실제 점유 사각형을 반사해 정수 원점을 반환한다. 본부의 물리 중심은 `(18,18.5)`, `(109,18.5)`, `(109,108.5)`, `(18,108.5)`이며 `start_worker_positions(slot)`도 네 일꾼의 출발 좌표를 반사한다.

각 본진 진입로는 같은 반경 4칸의 통로를 반사해 만들었다. 자동 검사는 반사된 입구의 보행 표본을 비교하고, 자원 및 네 본부를 장애물로 둔 3×3칸 대형 유닛의 실제 종단 경로도 검사한다. 입구 횡단 표본의 합계를 연속 최소 통로 폭으로 해석하면 안 된다.

## 자원 규격과 총량

각 지도에는 본진 4개·앞마당 4개·추가 확장 4개, 총 12개 기지가 있다. 모든 기지는 아스 8개와 테라 1개를 가진다.

| 항목 | 한 노드 | 기지 1개 | 지도 전체 |
| --- | ---: | ---: | ---: |
| 아스 | 1500 | 8개 / 12000 | 96개 / 144000 |
| 테라 | 5000 | 1개 / 5000 | 12개 / 60000 |

모든 노드는 `amount`와 `initial_amount`를 별도로 저장한다. 아스의 충돌 크기는 2×1칸, 테라는 4×2칸이다. 이 규격은 [BWAPI 공식 UnitType 자료](https://github.com/bwapi/bwapi/blob/main/bwapi/BWAPILIB/Source/UnitType.cpp)를 참고했다. 네 시작점은 같은 밀집 광물 곡선을 반사하므로 본부에서 각 노드로 접근하는 거리와 가능한 채취 면이 같다.

좌표는 자원 몸체의 실제 중심이다. 아스는 `(n+.5,m)`, 테라는 `(n+1.5,m+.5)`를 사용한다. 자원 사각형은 `Rect2(pos-size/2,size)`, 타일 원점은 `pos-(size-1)/2`이다. 테라의 4×2 정제소도 같은 사각형에 정확히 겹친다. 물체와 자원 사각형은 겹치지 않으며, 자원 전체가 보행 가능한 지면에 놓이고 모든 테라의 정제소 칸은 건설 가능하다.

`set_resource_obstacles(rects)`는 내비게이션에 정수 중심이 포함된 칸만 반영한다. `buildable_map`은 이 장애물과 분리해 정제소가 자신의 테라 위에 건설될 수 있게 했다. 고갈된 아스는 코어가 장애물에서 제거하고 테라 지형은 유지한다.

## 실제 화면 확인과 렌더링

`tests/terrain_preview.gd`는 실제 `ACTerrainRenderer`로 세 맵을 그린다. 지도 전체가 실제 viewport 안에 들어오도록 가로·세로 중 작은 길이에 맞추고, 네 시작점과 기지·자원을 표시한다. 결과는 `build/map-overview-0.png`, `map-overview-1.png`, `map-overview-2.png`이다.

게임 판정은 32px 직교 격자를 유지한다. 지면은 생성 재질, 큰 마름모의 완만한 색 변화, 부드러운 재질 마스크를 사용하며 개별 타일마다 테두리나 부피가 있는 3D 블록을 그리지 않는다. 물·도로·암반·다리는 실제 판정 분류에서 그린다. 장식은 이동 불가 암반 위에만 배치한다. 모든 지형 꼭짓점은 0..4096px 안에 제한하며, 메인 world canvas는 유닛·건물·자원도 같은 지도 영역에서 자른다.

안개는 원래 시야 상태를 부드러운 알파 texture로 보간하되 미발견 유닛·자원·장식의 노출 판정은 엄격히 유지한다. 기존 지면 단독 비교에서는 2,680 draw calls가 11개로 줄었고, 이후 고지 재질 층 추가에 따라 지도별 실제 command 수는 달라진다. 최초 정적 mesh 생성은 약 1초이며 최근 지도 3개를 캐시한다.

생성형 재질의 반복, 단순한 자연 지층과 다리 재질 표현은 남아 있다. 현재 결과를 상용 RTS 완성본과 같은 수준으로 검증했다고 표현하지 않는다.

## v0.4 지면 해상도와 높이

기존 아틀라스 한 재질의 실제 원본은 약 313×306px였다. 이를 넓고 비등방적인 UV로 늘려 확대 2.0에서 한 원본 픽셀이 화면 여러 픽셀을 차지했다. 새 지면은 `terrain_detail_0.png`·`terrain_detail_1.png`·`terrain_detail_2.png`의 실제 1254×1254px 원본을 각각 독립 텍스처로 읽는다. 기본 재질의 주기는 512 월드픽셀(16칸)이고 두 축의 밀도가 같은 45도 UV를 쓴다. 월드 1px당 원본 2.449텍셀, 확대 2.0에서도 화면 1px당 1.225텍셀이다. 10단계 밉맵과 재질별 선형 필터를 적용해 축소 시 반짝임을 줄이고 유닛·HUD 필터는 유지한다. 넓은 마름모 색 변화를 낮은 불투명도로 별도 합성하여 세밀한 입자와 큰 색 덩어리를 분리한다.

고도 1단계의 시각적 높이는 24px이다. 이동 가능한 고도 경계는 연결된 영역별 오르막으로, 이동 불가 경계는 절벽 면으로 표현한다. `terrain_relief_v4.png`의 윗줄 세 행성 절벽에서 실제 수직 암벽 부분만 독립 추출한다. 아랫줄은 원근이 포함된 오르막 오브젝트여서 지면 재질로 붙이지 않는다. 오르막 바닥은 원근 없는 생성 자갈 재질과 실제 경사 방향의 명암으로 표현한다. 원래 지형·보행·건설·자원 마스크는 바꾸지 않는다.

`ACMap.visual_elevation(point)`는 실제 16px 지면 메시와 동일한 삼각형 보간을 반환한다. 유닛·자원·장식의 발 위치와 화면 입력 역변환이 같은 표면을 사용한다. 경계 API `visual_boundary()`는 끝 좌표 128을 포함하는 1024개의 외곽 정점을 반환한다. 마지막 월드 렌더 단계의 검정 마스크는 이 실제 투영 외곽을 따르므로 남쪽 가장자리의 시각적 높이만큼 생기던 빈 띠까지 가린다. 정적 메시 한 번으로 그리며 맵 밖 오브젝트가 HUD 아래까지 새어 보이지 않게 한다.

급한 절벽에서는 서로 다른 논리 지점이 같은 화면 위치에 투영될 수 있다. 화면 입력은 반복 추측 대신 반칸 격자와 삼각형 대각선 경계를 나눈 선형 교차를 구하고 앞쪽 교차면을 선택한다. 따라서 가려진 논리 지점까지 유일한 역변환을 요구하지 않는다. 입력 담당의 세 맵 1728표본 검사는 재투영 오차 최대 0.00049px였으며, 중첩된 5개 표본에서도 앞쪽 교차면 선택을 확인했다.

`tests/terrain_quality_test.gd`는 실제 원본 크기·텍셀 밀도·밉맵·UV 유한성·전체 메시 경계·게임 데이터 불변성 및 6000개 표면 보간 위치를 검사한다. `tests/terrain_boundary_test.gd`는 실제 RTX 4070 렌더에서 남쪽 경계 밖으로 그린 가상 오브젝트가 검정으로 가려지고 안쪽 부분은 유지되는지 검사한다. 지형 전후 화면과 확대 1.0·1.5·2.0 측정값은 `build/terrain-v04-before-*`, `build/terrain-v04-after-*`에 저장한다. 이는 이미지와 샘플링의 개선 검증이며 상용 RTS와 동등한 전체 아트 완성도를 주장하는 지표는 아니다.

추가 피드백 67·68 반영 후 지형 품질 검사 3,705,926항목을 통과했다. 경계 GPU 17항목, 맵 대칭·자원·경로 22,491항목도 성공이다. 초기 v0.4의 NVIDIA RTX 4070/OpenGL 3.3 측정에서는 같은 화면의 세 맵×세 확대율을 각 45프레임 비교하여 평균 지면 draw CPU 변경 전 0.351ms, 변경 후 0.389ms였다. 상단 림·접촉 그림자 강화 전의 수치이므로 최신 비용 측정과 구분한다.

절벽 생성 이미지 전체를 짧은 벽에 늘리면 사선 끝부분이 작은 막대처럼 반복되므로 실제 수직 암벽 부분만 재질로 추출했다. 절벽 재질은 별도 타일 사각형이 아니라 같은 연속 지형 메시의 남향 높이 기울기에 합성하며, 높이 적용 후 실제 벽 면의 크기로 UV를 계산하여 세로 늘어짐을 방지한다. 밝은 상단 턱과 짙은 하단 접촉 그림자를 따로 합성하여 하얀 지형에서도 절벽을 구별한다. 오르막 재질도 원래 16px 삼각형을 그대로 재사용해 별도 쿼드가 평평해지거나 뜨지 않는다. 모든 절벽·램프·조명 정점이 원래 지면 정점과 일치하는지 검사한다. 추가67·68 대표 RTX 4070 캡처는 `build/terrain-v04-relief-map0.png`·`map1.png`·`map2.png`이다. 암벽 무늬의 반복과 단순한 도로 전이는 여전히 개선 여지가 있다.

전략적 가독성의 기준은 평지의 조용한 재질, 높은 지면의 밝은 턱, 어두운 수직 암벽과 하단 그림자, 그리고 턱 사이로 끊김 없이 연결되는 오르막이다. 특정 스타크래프트 원본 맵의 지형 구조나 아트가 재현되었다는 뜻은 아니다. 추가 참고 페이지의 이미지 CDN은 불러오지 못했으므로 그 원본 화면을 직접 관찰·대조했다고 기록하지 않는다. 최종 대표 화면은 지형 단독 검수용이며 실제 유닛·건물과의 가독성은 게임플레이 영상에서도 확인한다.

물은 기존 게임 지형의 짙은 청록색 `#112d3b`와 기존 텍스처·UV·색 배율을 유지한다. 귤 행성 메인 메뉴의 주황색 폭포 이미지는 별도 자산이며 지면 물의 공통 재질과 혼동하지 않는다.
