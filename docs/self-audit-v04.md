# 아스테라크래프트 v0.4 자체 점검

검수 기준: 2026-10-15, Godot 4.6 / Windows. 아래의 확인 결과와 남은 범위를 구분합니다.

1. **실제 내보내기 확인.** 새로 내보낸 PCK에서 게임 자산과 가져온 오디오 리소스를 읽는 검사를 통과했습니다. 원본 오디오 파일이 PCK에서 직접 열리지 않는 상태에서도 효과음과 제공받은 MP3의 실제 리소스 로드·재생을 확인했습니다. 최종 ZIP·체크섬·다운로드 파일은 별도의 최종 배포 검수 대상입니다. 근거: `final-v04-exported-content.log`, `final-v04-exported-audio.log`, `final-v04-exported-supplied-music.log`.

2. **건물 규격과 그림 비율.** 39개 건물의 역할별 대응 규격을 BWAPI 자료와 비교해 데이터·건설 미리보기·충돌에 반영했습니다. 세 본부는 4×3칸, 정제 건물은 4×2칸이며 아스는 2×1칸입니다. 그림과 차체·포탑 부품은 원본 가로세로 비율을 유지합니다. 규격의 참고와 게임 아트의 완성도는 서로 다른 항목이므로, 원작 그래픽을 그대로 재현했다고 판단하지 않습니다. 근거: [건물 규격 검토](building-footprints-v04.md), [렌더·입력 검토](render-input-v04.md).

3. **마지막 광물 밀집 배치 반영.** 세 맵의 각 광물선은 8개 노드를 14×4칸 곡선으로 모았습니다. 새 본부 몸체에서 약 2.83~3칸 떨어지며 안쪽 채취 통로를 확보했습니다. 자원 몸체 비겹침·전체 접근 경로를 검사했고, 3맵·종족 배치 회전·4슬롯의 실제 일꾼 12명 채취에서 모든 노드 사용과 고갈 후 마지막 짐 반납을 확인했습니다. 맵당 아스 96개×1,500, 테라 12개×5,000과 테라 위치는 유지했습니다. 근거: [가까운 광물 배치](compact-minerals-v04.md), `compact-minerals-v04-audit.json`.

4. **맵 구조의 정확한 범위.** 황철 분지·과숙의 심장·적월의 성역은 좌우·상하 반사 대칭인 독자적 4인용 맵입니다. 지형·높이·자원·본부 충돌·접근 경로의 대칭을 검사했습니다. 로스트템플·투혼·파이썬의 원본 지도를 정확히 복제한 맵은 아닙니다. 광물 재배치는 기존 지형·절벽·물·다리·입구 구조를 변경하지 않았습니다.

5. **채취·건설·이동 규칙.** 아스 한 노드의 동시 채취자는 한 명이며, 바쁜 노드를 받은 일꾼은 가까운 빈 노드를 다시 찾습니다. 채취 일꾼끼리 통과할 수 있어도 자원·건물·지형 충돌은 유지합니다. 본부 반납과 건설 착수는 일꾼 몸체가 건물 외곽에 가까이 도착한 뒤 진행됩니다. Shift 건설은 같은 일꾼의 순차 계획이며 다른 일꾼을 자동 호출하지 않습니다. 귤 일꾼은 묘목을 심은 뒤 생존합니다. 좁은 길·밀집 도착·큰 대상의 근접 공격·마지막 반납 회귀를 통과했습니다. 근거: [게임 규칙·상태 변경](gameplay-schema-v04.md).

6. **귤 배양체와 생산.** 기존 종족별 13종 외에 귤의 배양체를 별도 기술 개체로 구현했습니다. 개별 선택과 서로 다른 유닛으로 동시 변태, 같은 ID 유지, 취소 환불, 인구 예약과 사망 처리를 검사했습니다. 장식만 추가한 방식은 아닙니다. 생산 중인 항목을 포함한 생산 상한은 5개이며, 연구 명령은 전용 건물에서만 허용합니다. 근거: `citrus_brood_v04_test.gd`, `construction_queue_v04_test.gd`.

7. **UI·지형·입력.** 자원 아이콘과 남은 양, 최대 12기 선택, 개별 정보·명령·단축키, 지면·미니맵 공격 및 집결 입력을 실제 OpenGL 화면과 입력 회귀로 확인했습니다. 지형의 높이와 화면 좌표 역변환, 전면 절벽 선택도 검사했습니다. Godot의 마우스 제한 설정과 포커스 복구는 구현했지만, 관리 데스크톱에서 Windows의 정확한 커서 가둠 영역은 완전히 검증하지 못했습니다. 일반 데스크톱에서 추가 확인이 필요합니다. 근거: [렌더·입력 검토](render-input-v04.md).

8. **애니메이션의 남은 한계.** 39개 유닛 캐시, 117개 건설 단계, 의무병 힐 자세, 배양체 성장과 별도 차체·포탑을 연결했습니다. 다만 일반 유닛은 주로 저장된 9방향과 좌우 반사로 16방향을 표시합니다. 추가 보행 단계에는 기존 자세를 정렬·혼합한 파생 프레임이 포함되며, 모든 유닛의 완전한 신규 32방향 애니메이션은 아닙니다. 일부 원본 방향 반복과 차량 궤도 동작의 한계가 남습니다.

9. **효과음과 사용자 음악.** 효과음 51종과 의무병 힐 소리의 별도 재생을 확인했습니다. 제공받은 **Ironbound Frontier** MP3는 바위너구리 슬롯에 연결했고, 원본 SHA 일치와 Godot 재생 길이 약 221.854초, 실제 PCK 재생·루프를 확인했습니다. 메인 화면·귤·부엉이 음악 슬롯은 비어 있으며 다른 음악으로 임의 대체하지 않습니다. 불승인된 개발용 합성 BGM은 배포 대상에서 제외했습니다. 외부 사용자 WAV·OGG·MP3 교체 경로는 유지합니다.

10. **멀티플레이의 확인 범위.** 가입·로그인, 방·준비·래더 화면과 서버의 무작위 맵·스타팅 확정 규칙을 구현했습니다. 메뉴 검사는 모의 API를 포함하며, 관리 환경의 HTTP 접속 차단 때문에 실제 서버 API 왕복 일부는 검증을 마치지 못했습니다. 서로 다른 두 PC의 LAN·인터넷 대전, 방화벽·공유기를 통과하는 연결은 미검증입니다. 공용 인터넷 로비가 운영 중이라는 의미도 아닙니다. 근거: [멀티플레이 검토](multiplayer-v04.md).

11. **밸런스 실험의 해석.** 54개 지상 전투는 같은 아스·테라 예산 상한으로 미리 배치한 군대를 3개 조합·3개 종족 쌍·3시드·좌우 교대로 비교한 통제 실험입니다. 실제 소비 자원과 인구는 조합마다 다르고, 기술 건물 비용·경제 운영·수동 스킬 조작은 제외했습니다. 원거리 혼합·중장갑에서는 바위너구리, 근접 러시에서는 귤이 우세했으므로 이를 최종 종족 승률로 해석하거나 즉시 수치 조정하지 않았습니다. 시간초과 한 건은 교전 후 양군이 약 25칸 떨어져 시야를 잃은 경우였습니다. 추격·빠른 목표 도주도 별도로 확인했습니다. 근거: `matchup-v04-lab.json`, `matchup_v04_lab.gd`.

12. **시연과 성능의 한계.** 7분 플레이 시연은 기본 자원·일꾼에서 정상 명령으로 채취·건설·생산·교전을 진행했으며, 자원 추가나 유닛 직접 생성 영상이 아닙니다. 다만 마지막 광물 밀집 배치 이전 녹화이며, 한 맵·한 시드·두 종족의 경기로 승패 확정까지 촬영하지 않았습니다. 최신 광물 배치는 별도의 실제 채취 시뮬레이션으로 검증했습니다. 또한 이전 400유닛 밀집 벤치에서는 시뮬레이션 한 단계의 p95가 약 67ms였으므로, v0.4의 장시간 최대 인구 전투와 모든 PC의 안정적인 프레임률을 보장하지 않습니다. 근거: [플레이 시연 설명](gameplay-demonstration-v04.md), `benchmark-v03-final.json`.

13. **실행하지 않은 배포 작업.** 실제 GitHub 게시와 E: 드라이브 복사는 수행하지 않았습니다. 배포 스크립트가 준비되어 있다는 사실을 업로드·복사 완료로 표현하지 않습니다. 이 문서는 검수 기록이며, 최종 파일 제공과 저장 위치는 최종 전달 결과를 기준으로 확인해야 합니다.
