# 자원3/3·안개·상단·AI 후속 검증

사용자 최신 요청에 따른 배포10 이후 소스 수정이다. 공개 배포10의2/2 결과와 구분한다.

## 원본 파이썬 섬의 실제 배치

원본 SCM/SCX에서 가져온 광물100024(116.5,11),100043(9.5,116)의 채굴량은 각각1이다. 영구 광물로 취급하면 주변 본진의3칸 거리 검사에 걸리지만, 정상 채취 명령으로 없앤 뒤에는 본진을(116,6)/(7,117)에 설치할 수 있다. 세 종족×두 섬에서 실제 채취→이동→본진 기초 생성→비용1회 차감을 확인한54검사가 통과했다. 설치 시 지면 경계의 아스/테라 간격은 모두3칸이다.

앞선 ‘원본 섬의 공간이 부족하다’는 판단을 정정한다. 섬 확장이나 섬 전용 거리 예외가 필요 없다. 원본 지형·광물·테라·채굴량을 유지한다. 원본 게임 실행 파일을 실행해 촬영한 검증은 아니며, 실제 원본 맵 데이터를 대조하고 현 게임에서 정상 채취/건설을 재현한 결과다.

OpenBW의 일반 자원 기지 건설 검사도 자원 주변3타일 제외 영역을 검사하며 파이썬 섬 전용 분기를 두지 않는다. 참고 구현: https://github.com/OpenBW/openbw/blob/master/bwgame.h (`can_place_building`).

## 전체 본진·멀티의3칸

- 시작12개 본진을 원본 CHK 시작 위치의4×3 건설 격자에 맞춘다.
- 전체42기지(시작12+멀티30)의 정상 본진 위치를3/3으로 재계산한다. 광물 전용6곳은 아스3칸만 검사하며 테라를 추가하지 않는다.
- 테라36개 모두 원본 좌표와 같게 복원했다. 이전 시작9곳의1~2칸 보정도 제거했다. 원본 지형/광물/통로 변경은 없다.
- 파이썬 두 섬은 채굴량1 광물을 실제로 제거해야 건설할 수 있다. 계획표의 `requires_mining`은 이 조건의 기록이며, 실제 건설 판정을 우회하지 않는다.
- 초기 배치/수동 미리보기/일반 명령/도착 시 재검사/AI 확장이 같은 거리 규칙을 사용한다.
- 기존2/2 계획 생성기는 실행을 중단하도록 표시했다. 재생성은 `tools/plan_resource_spacing_3_20261025.py --apply`로 한다.

검증: 격자291검사,42기지×3종족126기초 건설948검사,백그라운드 미리보기18검사,테라 원본 대조62검사,세 맵×세 종족 실제1920×1080 화면9검사. 정제 건물도 테라에 정확히 겹치며 본진과3칸이다. 원본 지도 감사246132항목 통과.

## 같은 층에 남는 검은 안개

월드 클립은 솟은 지형을 포함하도록 확장되지만, 안개128×128마스크까지 이 확장 영역에 늘여 투영해 실제 지면과 어긋났다. 평면 마스크도 절벽의 높이 변화와 일치하지 않았다.

안개를 실제 지형과 같은16px 삼각형/높이/중심 좌표로 투영하고, 중첩된 절벽면은 투명 보조 뷰포트에서 먼저 합성한다. 지형 삼각형은 지도별로 보관하며 카메라/시야가 바뀔 때만 안개 표면을 갱신한다. 시뮬레이션 시야를 넓히거나 고저 판정을 지우지 않는다.

세 실제 맵에서 안개 표시/숨김 화면을 같은 지면 표본으로 비교했다. 배포10 투영에서는35곳이 잘못 어두워졌고, 수정본은 검사한137표본에서0곳이었다. 표본은 자기 시야의 안쪽 지면이며 절벽 뒤 숨은 지형을 공개하는 검사가 아니다. 고지대/피격 일시 노출/공중 시야37검사,시야 캐시4검사,건물 기억11검사 통과.

카메라 이동마다 안개 지형을 다시 그리지 않도록2048×2304 보관 이미지에 투영한 뒤 화면 위치만 바꾼다. 카메라 이동/줌/시야 변경/지도 전환의 캐시5검사와 실제 셰이더/200기 렌더7검사가 통과했다. 같은 장비의 화면 이동 평균은 기존100.8fps,수정103.3fps였으며95백분위 CPU 작업은3.02ms/2.78ms다. 정지 약144fps,숨은 적 이동 약117fps다. 장비별 절대 성능 보장이 아니라 이 회귀 실험에서 큰 성능 저하가 없었음을 확인한 수치다.

## 북쪽 화면과 AI 집결

카메라는 보이는 북쪽 경계의 최대 높이와 북쪽 유닛/건물의 실제 렌더 범위를 포함한다. 체력/실드 바도 남기며, 외곽 지형 가림을 유닛 뒤로 옮겨 합법 지면 위 몸체가 덮이지 않게 한다. 유닛 이동·지형 충돌·원화·화면비는 유지한다.

AI는 보이는 적과 공개 지형을 기준으로 목표 약16~28칸 앞 안전한 장소를 골라 집결한다. 각 유닛의 대기 자리를 유지하고 한 무리의 느린 동료까지 도착한 뒤 같은 판단 시점에 함께 공격 이동한다. 뒤늦은 생산 병력은 별도 무리로 합류하며, 큰 손실과 부상자는 재집결한다. 본진 피습 방어는 집결보다 우선한다.

통제 상황42검사와 세 원본 맵×세 종족9회 실제 이동에서 집결/대기/동시 진입을 확인했다. 가장 큰14기 무리도 원본 맵에서 세 종족 모두 집결 후 진입했다. 혼합 속도의 전열사수/전차는 먼저 도착한 병력이8.75초 기다린 뒤 함께 출발했다. 기존 AI 경제/생산/인구 제한140검사와90개 기습의 단계별 대응15검사도 통과했다. 해당 실험은 전진 집결 동작과 반응 순서를 확인하며 모든 상대 조합의 승리 시간을 보장하지 않는다.

북쪽의 전체 스프라이트와 체력/실드 표시51검사가 통과했다. 좌우와 아래는 맵 밖 검은 공간이 나오지 않는 선까지 허용하고, 위쪽만 유닛 표시를 위한 여유를 허용한다. 세 맵×세 종족의 좌/우/하단/하단 두 모서리를 관전자 최소1.0·일반 최소1.75·최대2.5배로 대조한다. 하단 지형 끝은 HUD 가장 낮은 굴곡 뒤2px에 둔다.

실행 결과135상황261검사와1920×1080 실제45화면 검사에서 좌우·아래 검은 틈0으로 통과했다. 검증25묶음과 소스 해시는 `docs/verification_resource_fog_ai_20261025/summary.json`에 보관했다. 새 릴리스를 게시한 결과가 아니며 기존 배포10은 변경하지 않았다.
